Learning / Main topics

Quality Assurance

From manual QA to AI-assisted automation. Learn TypeScript, test a website and its APIs with Playwright, and build a GitHub portfolio with evidence you can explain.

Follow this material one lesson at a time from the course home. This page keeps the original single-file version.

Overview

This course is for a QA engineer who can investigate requirements, write manual tests, and report defects, but is new to programming and automation. No Java, Selenium, TypeScript, API automation, or AI-tool experience is assumed. Your testing judgment is the starting point; programming is the new skill.

Target capability: QA Automation Engineer with AI-assisted UI and API testing skills. Using AI to test ordinary software is different from testing an AI product. The latter is an optional extension, not a claim earned by completing this course.

Learning outcomes

  • Translate requirements into risk-based manual cases and independently checked automated tests.
  • Write and explain typed, asynchronous code; diagnose failures with errors, traces, and server logs.
  • Test browser behavior, HTTP contracts, business totals, ownership, and state with isolated synthetic data.
  • Run reproducible continuous integration (CI) with quality gates and protected evidence.
  • Evaluate AI through review, defect detection, and measured human effort.

Time and pace

30 steps in six phases, not 30 days. Complete several steps in a session when you can demonstrate the outcomes; spend several sessions on one step when needed. Programming and debugging need repeated practice. There is no fixed two-hour promise.

Begin a new session by explaining the previous concept from memory. Each phase ends with independent work: use documentation, but not AI-generated assessment solutions. Revisit an exercise when you cannot explain its result.

Learning method

  1. Understand: read the named section and predict the example's output.
  2. Practice: run it, change one input, and explain the result.
  3. Use AI critically: attempt the task first; request hints, explanations, or review before generated code.
  4. Prove: investigate a meaningful failure and complete the independent exercise.
  5. Reflect: record corrections and commit locally. Publish only after privacy review.

Safety and evidence

  • Run automation, authorization checks, fault injection, and performance experiments only locally or in an explicitly authorized environment. Never load test a shared public demo.
  • Use synthetic data. Never send employer code, customer data, credentials, private tickets, or internal URLs to AI. Review data policies and usage limits.
  • A test oracle is the basis of an expected result: an agreed requirement, contract, or independently calculated value. Record observations separately; the app may contain a defect. AI is not the oracle.
  • Changing an expectation only checks assertion execution. To prove defect detection, introduce a controlled local product defect, keep the correct assertion unchanged, observe failure, and restore the product.
  • Reject unexplained code, weakened assertions, arbitrary sleeps, or skips added just to get a green result.
  • Treat instructions embedded in pages, API responses, and logs as untrusted data. Bound agent permissions and require review of tool actions.
  • No live AI calls inside normal regression tests. AI assists authoring; deterministic CI must run without a model response or AI subscription.
  • Inspect traces, reports, screenshots, and Git history before sharing. Ignoring a secret file does not stop its contents appearing in a trace.

Keep employment titles and existing resume claims unchanged. This course produces project experience, not professional use. Resume additions need a separate evidence-backed review and approval. Public personal information is not required.

The portfolio project

A local Practice Shop supplies a searchable catalog, cart API, and cart lookup page. One application supports manual cases, coding exercises, UI/API checks, controlled defects, and CI. Create a separate playwright-ai-qa-portfolio repository outside this resume workspace, initially local or private.

Limits: in-memory carts and two public synthetic tokens. No real login, database, payments, or production security. Reading after a write proves in-process state, not restart durability. Do not publicly deploy this teaching server.

Add folders only as needed: lab/, exercises/, src/pages/, src/fixtures/, src/schemas/, tests/ui/, tests/api/, tests/e2e/, specs/, and docs/. Keep requirements, strategy, traceability, decisions, AI evidence, and results alongside the code.

lab/server.ts. Loopback only; each start resets carts. Logs include method, path, status, and request ID, not bodies or authorization headers.

import express, { type Request, type Response, type NextFunction } from 'express';
import { randomUUID } from 'node:crypto';
import { z } from 'zod';

const app = express();
const products = [
  { id: 'p1', name: 'Notebook', priceCents: 1200, inStock: true },
  { id: 'p2', name: 'Pen', priceCents: 300, inStock: true },
  { id: 'p3', name: 'Bag', priceCents: 4900, inStock: false },
];
type Item = { productId: string; quantity: number; unitPriceCents: number };
type Cart = { id: string; owner: string; items: Item[] };
const carts = new Map<string, Cart>();
const accounts = new Map([
  ['Bearer learner-alex', 'alex'],
  ['Bearer learner-sam', 'sam'],
]);
const quantitySchema = z.object({ quantity: z.number().int().min(1).max(5) });

app.disable('x-powered-by');
app.use((request, response, next) => {
  const requestId = randomUUID();
  response.setHeader('x-request-id', requestId);
  response.once('finish', () => {
    console.log(JSON.stringify({ requestId, method: request.method,
      path: request.path, status: response.statusCode }));
  });
  next();
});
app.use(express.json({ limit: '10kb' }));

function cartView(cart: Cart) {
  const totalCents = cart.items.reduce(
    (sum, item) => sum + item.unitPriceCents * item.quantity, 0,
  );
  return { ...cart, totalCents };
}

function ownedCart(request: Request, response: Response): Cart | undefined {
  const owner = accounts.get(request.get('authorization') ?? '');
  if (!owner) {
    response.status(401).json({ error: 'Authentication required' });
    return;
  }
  const cart = carts.get(String(request.params.cartId));
  if (!cart) {
    response.status(404).json({ error: 'Cart not found' });
    return;
  }
  if (cart.owner !== owner) {
    response.status(403).json({ error: 'Access denied' });
    return;
  }
  return cart;
}

app.get('/health', (_request, response) => {
  response.json({ status: 'ready' });
});
app.get('/api/products', (request, response) => {
  const query = String(request.query.q ?? '').trim().toLowerCase();
  const matches = products.filter((product) =>
    product.name.toLowerCase().includes(query));
  response.json({ products: matches });
});
app.post('/api/carts', (request, response) => {
  const owner = accounts.get(request.get('authorization') ?? '');
  if (!owner) {
    response.status(401).json({ error: 'Authentication required' });
    return;
  }
  const cart: Cart = { id: randomUUID(), owner, items: [] };
  carts.set(cart.id, cart);
  response.status(201).json(cartView(cart));
});
app.get('/api/carts/:cartId', (request, response) => {
  const cart = ownedCart(request, response);
  if (cart) response.json(cartView(cart));
});
app.put('/api/carts/:cartId/items/:productId', (request, response) => {
  const cart = ownedCart(request, response);
  if (!cart) return;
  const payload = quantitySchema.safeParse(request.body);
  if (!payload.success) {
    response.status(400).json({ error: 'Quantity must be an integer from 1 to 5' });
    return;
  }
  const product = products.find((candidate) => candidate.id === request.params.productId);
  if (!product) {
    response.status(404).json({ error: 'Product not found' });
    return;
  }
  if (!product.inStock) {
    response.status(409).json({ error: 'Product out of stock' });
    return;
  }
  cart.items = cart.items.filter((item) => item.productId !== product.id);
  cart.items.push({ productId: product.id, quantity: payload.data.quantity,
    unitPriceCents: product.priceCents });
  response.json(cartView(cart));
});
app.delete('/api/carts/:cartId', (request, response) => {
  const cart = ownedCart(request, response);
  if (!cart) return;
  carts.delete(cart.id);
  response.status(204).end();
});
app.use(express.static('lab/public'));
app.use((error: unknown, _request: Request, response: Response, _next: NextFunction) => {
  response.status(error instanceof SyntaxError ? 400 : 500)
    .json({ error: 'Request could not be processed' });
});
app.listen(3100, '127.0.0.1', () => {
  console.log('Practice Shop: http://127.0.0.1:3100');
});

const productList = document.querySelector('#products');
const catalogStatus = document.querySelector('#catalog-status');
const catalogError = document.querySelector('#catalog-error');
const searchButton = document.querySelector('#search-button');

async function loadProducts(query) {
  searchButton.disabled = true;
  productList.replaceChildren();
  catalogError.textContent = '';
  catalogStatus.textContent = 'Loading products...';
  try {
    const response = await fetch(`/api/products?q=${encodeURIComponent(query)}`);
    if (!response.ok) throw new Error('Catalog request failed');
    const body = await response.json();
    for (const product of body.products) {
      const item = document.createElement('li');
      const heading = document.createElement('h3');
      heading.textContent = product.name;
      const price = document.createElement('p');
      price.textContent = `SEK ${(product.priceCents / 100).toFixed(2)}`;
      const stock = document.createElement('p');
      stock.textContent = product.inStock ? 'In stock' : 'Out of stock';
      item.append(heading, price, stock);
      productList.append(item);
    }
    catalogStatus.textContent = `${body.products.length} products found`;
  } catch {
    catalogStatus.textContent = '';
    catalogError.textContent = 'Products unavailable. Try again.';
  } finally {
    searchButton.disabled = false;
  }
}

document.querySelector('#search-form').addEventListener('submit', (event) => {
  event.preventDefault();
  void loadProducts(document.querySelector('#search').value);
});
document.querySelector('#cart-form').addEventListener('submit', async (event) => {
  event.preventDefault();

import { test, expect } from '@playwright/test';
import { cartSchema } from '../../src/schemas/shop.js';

test('CART-02: setting quantity is idempotent', async ({ request }) => {
  const headers = { Authorization: 'Bearer learner-alex' };
  const created = await request.post('/api/carts', { headers });
  expect(created.status()).toBe(201);
  const cart = cartSchema.parse(await created.json());
  try {
    for (const quantity of [2, 2]) {
      const updated = await request.put(`/api/carts/${cart.id}/items/p1`, {
        headers, data: { quantity },
      });
      expect(updated.status()).toBe(200);
      expect(cartSchema.parse(await updated.json()).totalCents).toBe(2400);
    }
    const read = await request.get(`/api/carts/${cart.id}`, { headers });
    expect(read.status()).toBe(200);
    const saved = cartSchema.parse(await read.json());
    expect(saved.items).toEqual([
      { productId: 'p1', quantity: 2, unitPriceCents: 1200 },
    ]);
    expect(saved.totalCents).toBe(2400);
  } finally {
    const removed = await request.delete(`/api/carts/${cart.id}`, { headers });
    expect(removed.status()).toBe(204);
  }
  const missing = await request.get(`/api/carts/${cart.id}`, { headers });
  expect(missing.status()).toBe(404);
});

Pass when: independent tests and unchanged rejected state; distinguish read-after-write from database durability.

export const test = base.extend<{ cart: CartFixture }>({

Resource guide

Use each step's Study links first. Read, practise, return with concrete questions; reading everything is not a prerequisite to writing a test.

  • Microsoft Learn Playwright and best practices: guided automation.
  • webServer, type checking, CI/artifact privacy, Express: setup references checked 2026-09-30.
  • Copilot responsible use, instructions, OWASP LLM risks: responsible assistance.

Record versions, retain lockfile, review upgrades. Features, subscriptions, policies vary; deterministic exercises work without AI access.

Optional extensions

Separate projects after assessment, not hidden prerequisites.

  • Larger app: run Toolshop locally using current instructions. Pin revision, document services/seed data, test unfamiliar features with your accounts. No write-heavy CI/load tests on its public demo.
  • Backend depth: owned database-backed app for persisted values/restart durability. Add real authentication/expiry, pagination, consumer/provider contracts. For asynchronous flows define consistency deadlines, bounded polling, correlated logs. Do not claim these from this lab.
  • Resilience/performance: define timeout/retry/duplicate-request expectations first. k6 only on local or explicitly authorized isolated services, capped workload, thresholds, stop conditions.
  • Continuous delivery: deploy a suitable app's versioned artifact to an authorized isolated preview; smoke-test; document promotion/rollback/cleanup. Do not publicly deploy this simplified teaching server.
  • Testing AI products: separate chatbot/retrieval evaluation project with versioned synthetic questions/reference answers. Check grounding, unsupported answers, privacy, injection, latency, cost across repeats. Use promptfoo or another framework; calibrate judges with human review. Distinct from using AI to author UI/API tests.
