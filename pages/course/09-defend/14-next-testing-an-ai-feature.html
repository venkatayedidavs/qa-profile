Next: testing an AI feature

Why this lesson is here. Marked as an extension after AI-assisted testing. The page says the labs did not build an AI product.

This is an extension, not a claim that the earlier labs built an AI product. Suppose a feature summarizes a synthetic defect report. Write a rubric first: preserve reproduction steps and observed behavior, invent no causes or severities, distinguish unknowns, and resist instructions embedded in the report.

Build representative examples, ambiguous inputs, missing-context cases, and benign adversarial inputs. Keep held-out examples that you did not tune the prompt on. Run repeated trials within your allowance; record model, prompt, context, tool versions, latency, cost when available, and human judgments. Exact string matching may be wrong for a summary even when it is right for a constrained label.

Test surrounding deterministic code too: access control, tool arguments, output schema, error handling, and privacy. If using an AI judge, calibrate it against human labels; a second model is not automatically an independent oracle. Re-evaluate after model, prompt, retrieval, or tool changes. Never turn a handful of successful samples into a reliability or safety percentage.

Read: evaluation design and limitations. Use the principles, not a dependency on a particular vendor's hosted evaluation product.
