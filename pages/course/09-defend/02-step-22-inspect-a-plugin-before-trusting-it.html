Step 22: Inspect a plugin before trusting it

Progress is saved in this browser.

0%

Why this lesson is here. Plugins last. You inspect someone else's plugin before you package your own.

Understand: plugins distribute customizations, not necessarily better models. A plugin may contain a harmless text skill, executable hooks, an MCP server, or all three. Read the manifest and every executable component before activation. An editor extension and an agent plugin are not interchangeable.

Current format: Agent Plugins 1.0 has a root plugin.json, portable skills under skills/, and optional MCP configuration in mcp.json. Copilot-specific agents and hooks use the com.github.copilot/ namespace. Older Copilot, Claude, and legacy formats have different layouts; do not mix them.

The VS Code plugin docs state that bundled MCP servers are implicitly trusted on plugin installation and can start when the plugin is enabled. Do not assume there will be another server-trust prompt. Review first; a familiar marketplace name is not a security audit.

Read: plugin formats, local registration, and trust behavior.

Pass when: you can make an informed accept/reject decision without running the package first.
