Separate projects after assessment, not hidden prerequisites.

  • Larger app: run Toolshop locally using current instructions. Pin revision, document services/seed data, test unfamiliar features with your accounts. No write-heavy CI/load tests on its public demo.
  • Backend depth: owned database-backed app for persisted values/restart durability. Add real authentication/expiry, pagination, consumer/provider contracts. For asynchronous flows define consistency deadlines, bounded polling, correlated logs. Do not claim these from this lab.
  • Resilience/performance: define timeout/retry/duplicate-request expectations first. k6 only on local or explicitly authorized isolated services, capped workload, thresholds, stop conditions.
  • Continuous delivery: deploy a suitable app's versioned artifact to an authorized isolated preview; smoke-test; document promotion/rollback/cleanup. Do not publicly deploy this simplified teaching server.
  • Testing AI products: separate chatbot/retrieval evaluation project with versioned synthetic questions/reference answers. Check grounding, unsupported answers, privacy, injection, latency, cost across repeats. Use promptfoo or another framework; calibrate judges with human review. Distinct from using AI to author UI/API tests.
