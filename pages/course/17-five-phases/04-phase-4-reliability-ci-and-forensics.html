Phase 4 — reliability, CI and forensics

Why this lesson is here. Forensics comes after there is a framework that can fail. The exit is a trace narration.

Study: the parallelism model; worker and parallel index; retries and retry strategy; maxFailures; trace modes; trace viewer; UI mode; reporters including blob and merge; sharding; Docker and OS consistency.

Do: introduce five flaky tests deliberately — a re-render race, a shared backend record, an animation, a time-dependent assertion and an unmocked third-party call — and fix each properly. Then run the suite sharded across a matrix, merge blob reports into one HTML report and publish it as an artifact.

Exit: given a failing trace, narrate the diagnosis out loud in senior order: what the test intended, what the DOM showed at the failing action, what the network did, then the fix.
