Use it in everyday engineering

Why this lesson is here. The original page places everyday use after the steps, and points UI and API automation back at the Quality Assurance path.

TaskA useful bounded requestYour acceptance check
Requirements and QA planningIdentify ambiguities; keep proposed rules separate.A product owner confirms the rule; cases trace to it.
Test design and automationReview boundaries or explain one assertion.Independent expectations; real test run; deliberate defect detected.
Code comprehensionExplain a named function using its callers and tests.Open the cited code and reproduce an input/output example.
DebuggingGive one hypothesis and a cheap check from a sanitized failure.The check distinguishes causes; the repair addresses the observed cause.
Implementation and refactoringPropose the smallest change inside named files.Review diff, types, tests, compatibility, and unrelated changes.
Documentation and code reviewSummarize only the verified diff and test results.Every behavior claim has evidence; unrun checks stay unrun.

For UI and API automation, continue with the QA course. Keep live AI out of ordinary deterministic regression tests. Review AI-generated dependencies, licenses, data handling, and commands before adopting them.
