When something does not work

Why this lesson is here. The symptom table comes after the features that fail in these ways.

SymptomFirst checkEvidence to collect
Customization missingSelected harness, lab root, exact path/extension, valid YAML or JSONCustomizations listing and discovery errors
Skill listed but not usedExplicit slash invocation, descriptive trigger, invocation flagsReferences and actual skill/resource loading
Instructions absentGlob, changed file, relevance or attachment; in Local also check chat.includeApplyingInstructions and github.copilot.chat.codeGeneration.useInstructionFilesLoaded instructions and a representative task result
Prompt command absentAgent Host does not load prompt files; use a skillSession target and supported customization type
Reviewer can edit or run commandsActive agent, effective tool list, prompt override, client-specific tool aliasesActual exposed tools and before/after file contents; stop until resolved
Hook appears but never asksRuntime/schema pair, event, trust/policy, executable path, working directoryHook input, output, and sanitized runtime errors; do not assume protection
Hook works offline but fails in chatDiscovery and runtime wiring, not only script logicSeparate script-test result and live integration result
Every tool is denied with a valid-looking configLocal can parse a Copilot-format config but still sends Local-shaped input. In Local, use the Local config and the script's local argument.Compare the actual event payload with the selected script format
Plugin or its skill missingFormat marker, local registration, enabled state, matching skill folder/nameSource location and namespaced command in a fresh session
Confident but wrong resultMissing/old context, unsupported assumption, incorrect oracleSmall reproducible input, authoritative rule, actual output
Quota, account, or policy blocks a labOfficial allowance and supported features; ask the administrator where appropriateMark live work blocked; continue reading and offline tests without bypassing controls

Use Developer: Open Agent Debug Logs when available; older versions may expose Diagnostics from the Chat view. Logs can contain prompts, paths, and tool data. Review and sanitize them before sharing; do not upload a full transcript to troubleshoot one error.
