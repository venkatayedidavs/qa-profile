Step 17: Understand events, input, and decisions

Progress is saved in this browser.

0%

Why this lesson is here. Events, input, and decisions come before the approval script.

Understand: a pre-tool hook runs before an agent tool; a post-tool hook runs after a successful tool call. A post-tool hook cannot undo a message already sent or a file already changed. A Git hook runs at a Git event; a test hook runs in a test framework. They are different lifecycles.

Supported targets for this lab: Local and Copilot only. If your selected target is Claude, Codex, or another runtime, continue with the offline tests but mark live activation as blocked until you follow that provider's hook reference. Choosing an Anthropic model inside a Copilot session does not select the Claude harness.

This teaching hook: receive JSON describing a tool request, ask for approval for every valid event, and deny malformed input. It neither executes the requested tool nor interprets its arguments as shell code.

Agent requests a tool
  -> harness sends event JSON to the hook's stdin
  -> hook returns a JSON decision on stdout
  -> harness asks the person, or denies the request
  -> permitted tool runs and returns its result

Vocabulary: stdin is input to a process; stdout is its normal output; stderr is its diagnostic output. An exit code reports whether the process completed successfully. The harness decides how those outputs affect the pending action.

Read: choose the hook implementation, Local reference, and Copilot reference.

Pass when: you can identify the runtime and explain who requests, decides, approves, and executes.
