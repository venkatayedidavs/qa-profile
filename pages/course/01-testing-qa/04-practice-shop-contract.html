Practice Shop contract

Why this lesson is here. The lab is reading this contract and saying what done means. Later tests treat these IDs as the oracle.

These are agreed teaching requirements, not expectations inferred from implementation. Keep them unchanged while testing deliberate defects.

IDRequired behaviorIndependent example
CAT-01Three products; API prices are integer minor units.p1: Notebook, 1200, in stock. p2: Pen, 300, in stock. p3: Bag, 4900, out of stock.
CAT-02GET /api/products?q=... trims spaces and matches a case-insensitive name substring. Blank/missing query returns all in seed order. Status 200; body { products: [...] }.NOTEBOOK and spaced notebook return p1 only; zzzz returns an empty array.
UI-01Show names, SEK prices, and count. Failed requests show an error instead of stale results.Notebook: SEK 12.00. Empty: 0 products found. Failure: Products unavailable. Try again.
CART-01POST /api/carts creates an empty owned cart: new ID, 201. GET by ID reads it; DELETE removes it with 204. Missing cart: 404.Two creates yield different IDs; reading after deletion returns 404.
CART-02PUT /api/carts/:id/items/:productId accepts JSON integer quantity 1 to 5 inclusive. Sets, not increments, quantity; returns cart with 200.Two identical writes of two notebooks leave one line, quantity 2, total 2400. Invalid quantity: 400; unknown product: 404; unavailable stock: 409.
AUTH-01Cart operations need a recognized bearer token. Missing/unknown: 401. Wrong owner on an existing cart: 403.Bearer learner-alex and Bearer learner-sam are distinct synthetic users, never real credentials.
UI-02The cart lookup uses synthetic Alex and displays the server total.Two notebooks: Cart total: SEK 24.00. Failure: Cart unavailable.

Reasoning example: quantities 0, 1, 5, 6 cover boundaries; string "2" checks the JSON type. Calculate totals independently. Two screens agreeing is weak evidence if both use the same faulty calculation.
