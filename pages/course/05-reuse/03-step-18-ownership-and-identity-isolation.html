Step 18: Ownership and identity isolation

Progress is saved in this browser.

0%

Why this lesson is here. Two users come after shared setup, because a browser context does not isolate server-side carts.

Outcome: authorization with controlled identities. Fixed tokens do not cover login, JWT verification, expiry, MFA, OAuth.

Study: authentication. Reuse login state only without interfering server state; login tests themselves start unauthenticated.

tests/api/ownership.spec.ts

import { test, expect } from '../../src/fixtures/shop.js';

test('AUTH-01: Sam cannot read Alex cart', async ({ cart, playwright, baseURL }) => {
  const otherUser = await playwright.request.newContext({
    baseURL, extraHTTPHeaders: { Authorization: 'Bearer learner-sam' },
  });
  try {
    const response = await otherUser.get(`/api/carts/${cart.id}`);
    expect(response.status()).toBe(403);
    expect(await response.json()).toEqual({ error: 'Access denied' });
  } finally {
    await otherUser.dispose();
  }
});

Pass when: demonstrate rejected access and preserved state, not comprehensive security claims.
