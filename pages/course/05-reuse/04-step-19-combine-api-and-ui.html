Step 19: Combine API and UI

Why this lesson is here. The combined journey uses API arrangement and the page object from the previous steps.

Outcome: follow real data across layers and distinguish mocked UI errors from real integration.

Study: API plus UI, mocking.

tests/e2e/cart.spec.ts

import { test, expect } from '../../src/fixtures/shop.js';

test('UI-02: cart shows the independently calculated total', async ({ page, cart }) => {
  const updated = await cart.client.put(`/api/carts/${cart.id}/items/p1`, {
    data: { quantity: 2 },
  });
  expect(updated.status()).toBe(200);
  await page.goto('/');
  await page.getByLabel('Cart ID').fill(cart.id);
  await page.getByRole('button', { name: 'Load cart' }).click();
  const cartSection = page.getByRole('region', { name: 'Cart' });
  await expect(cartSection.getByRole('status')).toHaveText('Cart total: SEK 24.00');
});

tests/ui/catalog-error.spec.ts checks UI reaction, not the real API's outage handling.

import { test, expect } from '@playwright/test';

test('UI-01: reports an unavailable catalog', { tag: '@mocked' }, async ({ page }) => {
  await page.route('**/api/products?*', (route) => route.fulfill({
    status: 503, contentType: 'application/json',
    body: JSON.stringify({ error: 'Unavailable' }),
  }));
  await page.goto('/');
  const catalog = page.getByRole('region', { name: 'Catalog' });
  await expect(catalog.getByRole('alert')).toHaveText('Products unavailable. Try again.');
  await expect(catalog.getByRole('listitem')).toHaveCount(0);
});

Pass when: independently calculated expectations, not just two matching outputs.
