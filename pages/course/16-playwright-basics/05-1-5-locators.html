1.5 Locators

Why this lesson is here. How a test finds elements, after you know a page is a tab in a context.

A locator is a lazy description of how to find elements. It is re-resolved immediately before every action, so a re-render between two lines of your test does not produce a stale element error. This is the single biggest day-to-day difference from Selenium's WebElement.

Recommended priority, highest first:

  1. getByRole('button', { name: 'Sign in' }) — matches how users and assistive technology perceive the page.
  2. getByLabel() for form controls.
  3. getByPlaceholder(), getByAltText(), getByTitle().
  4. getByTestId() — an explicit contract with developers; the attribute is configurable via testIdAttribute.
  5. page.locator('css') or XPath — last resort, because both couple tests to DOM structure.
// chaining and filtering instead of brittle CSS chains
const row = page.getByRole('listitem').filter({ hasText: 'Product 2' });
await row.getByRole('button', { name: 'Add to cart' }).click();

// alternatives and combinations
page.getByRole('button').and(page.getByTitle('Subscribe'));
newEmailButton.or(securityDialog).first();
page.locator('button').visible();
What is strict mode?

Locators are strict by default: if an action targets a locator that matches more than one element, Playwright throws instead of silently acting on the first. Multi-element operations such as count() are fine. Resolve a violation by narrowing with role plus accessible name, chaining inside a container, or filter(). Reaching for first() or nth() is an admission that the locator does not express intent.

Why prefer role locators over CSS?

They survive styling and markup refactors, they read like the user's experience rather than the implementation, and they give early feedback on accessibility because a missing accessible name breaks the locator. They do not replace an accessibility audit, but they surface obvious gaps continuously.

Does Playwright handle shadow DOM and iframes?

Locators pierce open shadow roots by default; the exceptions are XPath, which does not pierce, and closed shadow roots, which are unsupported. For iframes use frameLocator(), which waits for the frame and then scopes the search inside it.
