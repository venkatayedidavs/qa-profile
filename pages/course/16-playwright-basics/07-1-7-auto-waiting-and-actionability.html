1.7 Auto-waiting and actionability

Why this lesson is here. The checks every action from the previous lesson actually performs.

Playwright performs actionability checks before acting and retries until they pass or the action times out. Knowing this list by name is a strong signal in interviews.

  • Attached — present in the DOM.
  • Visible — non-empty bounding box, not visibility: hidden.
  • Stable — has stopped moving between animation frames.
  • Receives events — nothing else overlays the hit point.
  • Enabled — not disabled.
  • Editable — additionally required for typing.

Consequence: explicit sleeps are unnecessary and harmful. page.waitForTimeout() exists for debugging only.

Why does an action still fail even though the element is on screen?

Usually because an actionability check other than visibility is failing: an overlay, a cookie banner or a toast intercepting the click point, or an animation still running so the element is not stable. The timeout error includes an actionability log naming the check that blocked, and the trace shows the DOM at that moment.

What do you do about a cookie banner that appears unpredictably?

page.addLocatorHandler() registers a dismissal handler that fires whenever the interstitial appears, with a times limit. Better still, suppress it at source with a pre-set cookie or a route stub so no test spends time on it.

Read this aloud if you want the spoken pass. The course does not include a recording. The same words are in the script file next to this lesson.

Before Playwright clicks, it does not trust that the element is merely on the page. It retries a list of actionability checks until they pass, or until the action times out.

Attached means the element is in the DOM.
Visible means it has a non-empty box and is not hidden.
Stable means it has stopped moving between animation frames. If a control is still sliding, the click waits. That is what stable means for an animating element.
Receives events means nothing else covers the point you are clicking. An overlay, a toast, or a cookie banner fails this check even when you can see the button.
Enabled means it is not disabled.
Editable is an extra check, required when the action types.

If a check fails, the timeout error names the check that blocked. That log is the diagnosis. Do not add waitForTimeout to hide it. That call is for debugging, not for a test you keep.

You should be able to say this list without notes. That is the exit this part of the plan asks for.
