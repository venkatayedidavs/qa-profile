1.1 What Playwright is and how it drives a browser

Why this lesson is here. First, because locators and fixtures assume you know which product the word Playwright means.

Playwright is a browser automation and test-running framework from Microsoft. It ships two things that are easy to confuse: the Playwright library for driving browsers, and Playwright Test (@playwright/test), the test runner with fixtures, parallelism, reporters and assertions. In interviews, "Playwright" almost always means the test runner.

It drives Chromium, Firefox and WebKit from a Node.js process over a single persistent connection, using each browser's own automation protocol. Two consequences matter and both come up in interviews: it can create many cheap isolated browser contexts, and it can observe and intercept network traffic below the page, which an in-browser runner cannot do as easily.

What is the difference between the Playwright library and Playwright Test?

The library automates browsers and can be embedded in any Node.js program, for example a scraping or monitoring script. Playwright Test adds the test runner: fixtures, parallel workers, projects, retries, web-first assertions, reporters, traces and the CLI. Installing @playwright/test gives you both; you do not install playwright alongside it.

Which browsers does Playwright support, and does it use the real browsers?

Chromium, Firefox and WebKit, downloaded as Playwright-managed builds so versions are pinned and reproducible. It can also run against installed branded channels such as Google Chrome and Microsoft Edge via the channel option, which is what you use when a stakeholder insists on testing "real Chrome". WebKit is the practical way to get Safari engine coverage on Linux CI.
