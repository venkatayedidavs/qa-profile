Step 1: Connect manual QA to automation

Why this lesson is here. The phase starts by separating idea, procedure, action, assertion, and evidence. The code lessons assume that split.

Outcome: distinguish idea, procedure, action, assertion, and evidence. Automation does not replace exploration.

Study: the contract and actions/assertions, concepts before syntax.

Pass when: independently explain an assertion and one risk still needing exploration.

Voiceover script

Read this aloud if you want the spoken pass. The course does not include a recording. The same words are in the script file next to this lesson.

Before any syntax, separate five things.

The idea is the risk you care about. The procedure is the manual case: preconditions, steps, and the expected result. The action is what a person does, such as searching for NOTEBOOK. The assertion is the check against the contract: the name, the count, and the price. The evidence is what you actually observed.

Automation does not replace exploration. A test that only checks that the page opened has not tested search.

Write the manual NOTEBOOK case first, with the contract IDs on it. If you use an AI tool, ask for one missing negative case, then log what you tried, what it suggested, and what you corrected. Do not invent a mistake you did not make.

You are done with this lesson when you can explain an assertion, and name one risk that still needs a person to explore.
