Why this lesson is here. The first API spec follows the conversation you just read, and it does not go through the UI.

Outcome: verify API behavior independently of UI. Request is an HTTP fixture; params encodes the query.

Study: API testing, APIRequestContext.

tests/api/catalog.spec.ts

import { test, expect } from '@playwright/test';

test('CAT-02: API search ignores case', { tag: '@api' }, async ({ request }) => {
  const response = await request.get('/api/products', { params: { q: 'NOTEBOOK' } });
  expect(response.status()).toBe(200);
  expect(response.headers()['content-type']).toContain('application/json');
  const body: unknown = await response.json();
  expect(body).toEqual({
    products: [{ id: 'p1', name: 'Notebook', priceCents: 1200, inStock: true }],
  });
});

Pass when: wrong prices fail despite HTTP 200.
