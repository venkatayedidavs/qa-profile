Step 13: Negative cases and data

Why this lesson is here. Invalid quantities, unknown products, and the wrong owner come after the happy-path contract test.

Outcome: partitions become independently named tests, not hidden checks in one scenario.

Study: parameterization, AUTH-01.

tests/api/access.spec.ts

import { test, expect } from '@playwright/test';

const cases: { name: string; headers: Record<string, string> }[] = [
  { name: 'missing token', headers: {} },
  { name: 'unknown token', headers: { Authorization: 'Bearer not-a-user' } },
];

for (const scenario of cases) {
  test(`AUTH-01: rejects ${scenario.name}`, async ({ request }) => {
    const response = await request.post('/api/carts', { headers: scenario.headers });
    expect(response.status()).toBe(401);
    expect(await response.json()).toEqual({ error: 'Authentication required' });
  });
}

Pass when: distinguish empty success, invalid input, unauthorized access.
