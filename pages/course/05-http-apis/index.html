HTTP and API

Quality Assurance steps 11 through 15. Complexity rises from the UI test to HTTP. Review a generated contract the way the AI slides say to review a suggestion.

Why this module is here. Quality Assurance steps 11 through 15. Complexity rises from the UI test to HTTP. Review a generated contract the way the AI slides say to review a suggestion.

What it unlocks. Reuse, after there are tests worth sharing.

Prerequisite: Phase 2 gate. Outcome: contracts, business rules, and state transitions before abstractions.

  1. Lesson 1 Step 11: Read HTTP conversations

    Read methods, status codes, and headers before you assert them in a script.

  2. Lesson 2 Step 12: First API contract test

    The first API spec follows the conversation you just read, and it does not go through the UI.

  3. Lesson 3 Step 13: Negative cases and data

    Invalid quantities, unknown products, and the wrong owner come after the happy-path contract test.

  4. Lesson 4 Step 14: Schemas versus business rules

    A schema that accepts the negative cases from the previous step would be a false pass.

  5. Lesson 5 Step 15: State, idempotency, cleanup

    Stateful cart writes come after single-call contracts. Cleanup is the phase gate.
