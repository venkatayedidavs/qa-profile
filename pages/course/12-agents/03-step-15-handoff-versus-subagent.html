Step 15: Handoff versus subagent

Progress is saved in this browser.

0%

Why this lesson is here. Handoff and subagent are compared after a reviewer role exists to hand work to.

Manual handoff: review a finding, switch to a general-purpose agent, and provide only the approved change and relevant evidence. Ask for a plan first. Review that plan before authorizing edits. Changing roles can change the tool boundary.

Optional delegation: from a main agent with reading, searching, and subagent capabilities, use the prompt below. Agent names are case-sensitive. This is useful for a bounded review, not a reason to enable every tool.

Use the QA Reviewer subagent to review specs/quantity.md,
src/quantity.mjs, and test/quantity.test.mjs.
No edits or command execution. Return supported findings with file
locations, requirement IDs, and suggested verification.
After it returns, summarize the findings; do not implement them.

A subagent gets a separate working context and returns a result. For Local, provide a self-contained task because it does not inherit the full conversation; do not assume memory across invocations. A handoff continues work in a different role. Neither gives an independent proof of correctness.

Read: subagents by harness. Skip advanced orchestration until one agent demonstrably meets the need.

Pass when: the next participant gets enough context, with explicit permissions, and a person still verifies the result.
