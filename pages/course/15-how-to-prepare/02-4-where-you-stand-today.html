4. Where you stand today

Why this lesson is here. The plan inventories one resume before study, so the gaps name what the phases practise. Treat it as that plan's example.

Taken from the approved base resume and evidence file, not from assumption.

Strong and interview-ready

  • End-to-end QA ownership: requirements through test design, test data, manual execution, defect management and release validation.
  • Test management tooling: Jira, Xray, TestRail, Confluence.
  • API breadth: REST, SOAP, Bruno, RestAssured, Postman, SoapUI, Karate, OpenAPI, microservices.
  • Selenium WebDriver with Java, TestNG, Page Object Model, parallel execution, Jenkins, cross-browser on Chrome, Firefox and Safari.
  • CI/CD execution with GitHub Actions and Jenkins, plus k6 performance testing.
  • Regulated-domain testing: AML/KYC, sanctions, PEP/RCA, eID and BankID.
  • On-call incident investigation, log reading and defect narrowing.

Claimed on the resume, therefore fair game for deep questioning

  • A TypeScript and Playwright framework for regression and accessibility testing across customer-onboarding flows.
  • Playwright running in CI/CD pipelines with coverage reporting.
  • Cypress suites during the freelance period.
  • AI-assisted QA with GitHub Copilot and Claude Code, custom agents and skills.

Likely weak points to close before interviews

  • TypeScript as a language rather than "JavaScript with types": generics, unions, narrowing, structural typing.
  • Fixtures as an architecture, not a beforeEach replacement.
  • Deliberate flakiness diagnosis using traces rather than retries.
  • Sharding, blob reports and report merging at scale.
  • Network interception and mocking as a test-design tool.
  • Newer surface area: aria snapshots, clock control, test locks, Playwright test agents.
