Why this lesson is here. Persistent repository instructions come after you have seen an unguided suggestion, so you know what the file is for.

Create: .github/copilot-instructions.md in the practice lab. These are short project conventions, not a long tutorial.

## Practice lab conventions

- Use [the quantity contract](../specs/quantity.md) as the test oracle.
- Separate confirmed behavior, observations, and open questions.
- Keep changes within the requested files and behavior.
- After quantity code or test changes, run:
  node --test test/quantity.test.mjs
- Report the actual command and result, or state that it was not run.
- Preserve correct assertions when investigating a failure.
- Use synthetic data; ask before network access or installing packages.

Read: instruction formats and verification. AGENTS.md is another supported project format in several clients, not a custom-agent definition. Do not duplicate contradictory rules across both files.

Pass when: you have loading evidence and a checked result, not merely an existing file.
