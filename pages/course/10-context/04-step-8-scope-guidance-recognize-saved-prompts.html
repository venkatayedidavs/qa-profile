Why this lesson is here. File-scoped guidance and saved prompts come after repository-wide instructions. This is the phase gate.

Create: .github/instructions/tests.instructions.md. The glob is relative to the workspace root and applies when matching files are created or modified. A description also supports task-relevance discovery.

---
description: "Use when creating or reviewing quantity unit tests."
applyTo: "test/**/*.test.mjs"
---

## Test conventions

- Use node:test and node:assert/strict.
- Name each case so the input is recognizable in failure output.
- Derive expected values from the contract, not the function under test.
- Include a relevant negative case when adding behavior coverage.

Optional Local-only compatibility example: .github/prompts/explain-quantity.prompt.md. Invoke /explain-quantity in a supporting Local chat. Current Agent Host sessions do not load prompt files; skip this example there and use the skill in Phase 3. This is not a required setup step.

The agent: ask field selects the Ask role for this explanation request. It is a role setting, not a model name.

---
description: "Explain the quantity contract without changing files."
agent: ask
---

Read [the contract](../../specs/quantity.md).
Explain accepted values, rejected types, and one boundary pair.
Separate requirements from questions. Do not claim test execution.

Pass when: guidance applies for the intended reason. A nonmatching glob does not mean the file is forbidden from being loaded by relevance or attachment.
