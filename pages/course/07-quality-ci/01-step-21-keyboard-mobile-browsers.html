Why this lesson is here. Keyboard, mobile, and a second browser come after the core journey already passes.

Outcome: beyond desktop happy paths. Automated scans do not prove accessibility or replace manual evaluation.

Study: accessibility, emulation, projects.

Install npm install --save-dev --save-exact @axe-core/playwright; create tests/ui/accessibility.spec.ts.

import { AxeBuilder } from '@axe-core/playwright';
import { test, expect } from '@playwright/test';

test('UI-01: catalog has no detected axe violations', { tag: '@a11y' }, async ({ page }) => {
  await page.goto('/');
  const catalog = page.getByRole('region', { name: 'Catalog' });
  await expect(catalog.getByRole('status')).toHaveText('3 products found');
  const results = await new AxeBuilder({ page }).analyze();
  expect(results.violations).toEqual([]);
});

Run npx playwright install firefox webkit. Add these entries inside the existing projects array:

{ name: 'ui-firefox', testMatch: '**/ui/**/*.spec.ts',
  use: { ...devices['Desktop Firefox'] } },
{ name: 'ui-mobile-webkit', testMatch: '**/ui/**/*.spec.ts',
  use: { ...devices['iPhone 13'] } },

Pass when: named browser/device results, keyboard evidence, scan limits. Visual snapshots are optional; review baselines on a consistent OS.
