Step 11: Invoke it and verify discovery

0%

Why this lesson is here. Discovery is evidence the files are wired, which you cannot check before they exist.

Do: inspect Skills in Chat: Open Customizations, then start a fresh chat with read/search tools only. Type /qa-case-review and select it from the menu. Supply the contract path explicitly:

/qa-case-review Use specs/quantity.md as the requirement file.
Propose the cases in chat only; do not edit files or run commands.

Then try a natural-language request in a separate chat: "Review specs/quantity.md for boundary cases and invalid input types." Automatic discovery makes a skill available, not guaranteed to be chosen. Inspect References and available debug logs for the actual skill and checklist reads, then inspect the answer.

Invocation controls: by default the skill can be chosen automatically or invoked manually. disable-model-invocation: true makes invocation manual in supporting clients; user-invocable: false hides the slash command. Leave both out in this example. A hidden command is not a permission boundary.

Pass when: you can distinguish a discovery problem from a loaded skill that produced a poor answer.
