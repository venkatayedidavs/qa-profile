Overview

Why this lesson is here. The original page opens with who this is for and what done means, before any exercise.

This course is for a QA engineer who can investigate requirements, write manual tests, and report defects, but is new to programming and automation. No Java, Selenium, TypeScript, API automation, or AI-tool experience is assumed. Your testing judgment is the starting point; programming is the new skill.

Target capability: QA Automation Engineer with AI-assisted UI and API testing skills. Using AI to test ordinary software is different from testing an AI product. The latter is an optional extension, not a claim earned by completing this course.

Learning outcomes

  • Translate requirements into risk-based manual cases and independently checked automated tests.
  • Write and explain typed, asynchronous code; diagnose failures with errors, traces, and server logs.
  • Test browser behavior, HTTP contracts, business totals, ownership, and state with isolated synthetic data.
  • Run reproducible continuous integration (CI) with quality gates and protected evidence.
  • Evaluate AI through review, defect detection, and measured human effort.

Time and pace

30 steps in six phases, not 30 days. Complete several steps in a session when you can demonstrate the outcomes; spend several sessions on one step when needed. Programming and debugging need repeated practice. There is no fixed two-hour promise.

Begin a new session by explaining the previous concept from memory. Each phase ends with independent work: use documentation, but not AI-generated assessment solutions. Revisit an exercise when you cannot explain its result.
